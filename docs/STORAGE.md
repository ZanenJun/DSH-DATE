# 分月日历、每日必做、习惯与三个月同步

插件使用配置中的 `dataDir`，目录结构为：

```text
data/
  calendar.json              # schemaVersion 2 / layoutVersion 2，月份及集合索引、整体 revision 和时区
  calendar/
    2026-09.json              # 该月的事项与提醒执行状态；有数据时创建
    2026-10.json
    2026-11.json
  daily-tasks.json           # 每日必做模板，不包含生成后的日历实例
  habits.json                # 习惯规则和当次提醒状态，不包含催促正文
  history.json               # 近期变更/回复/催促记录，以及提醒的 lastText
  state.json                 # 幂等回执、去重标记、同步映射、待发送操作、冲突和运行状态
  balance.json               # 开启余额功能后独立保存的查询缓存、告警及冷却状态，无 API key
  backup/                    # 上一次提交的同结构分文件快照
  legacy/                    # 首次迁移保留的原版混合 JSON，仅作备份
  .transaction.json          # 提交期间的内部恢复日志，提交完成后删除
  icloud-credentials.json    # 原有独立凭据文件，权限 600
```

事项按配置时区的 **开始时间月份** 归档。改期跨月会将同一个 ID 移到目标月份，不复制成新事项；原月份即使变空也保留文件。每日必做模板保存在 `daily-tasks.json`，生成的普通待办按开始月份保存，并携带只读 `dailyTaskId` / `dailyDate` 标识。习惯规则与其 occurrence 保存在 `habits.json`；普通待办的提醒执行状态按 occurrence 的到期月份保存。月度日历文件不保存聊天正文、催促正文或历史对话数组。日程自己的标题/备注属于日历内容。

`history.json` 保留原有最近 200 条插件记忆策略，未新增自动清理历史月度日历的策略；DSH 自身的完整聊天会话仍由 DSH 存储，本次不迁移 DSH 原生会话数据库。`state.json` 内同步基线、待发请求及幂等回执可能包含日历字段的技术副本，供冲突和重试使用，不是聊天记录。

## 一致性与迁移

服务启动时自动迁移原 schemaVersion 1 文件：先将原 `calendar.json` 及旧 `.backup` 复制到 `legacy/`，再写入新的布局。ID、事项 revision、提醒确认状态、记忆、幂等回执和 iCloud 映射全部保留。旧文件备份不参与后续同步。现有分月布局也会升级：从各月文件中分离 `kind=habit` 规则和其 occurrence 到 `habits.json`，保留 ID、revision、提醒确认状态与历史。新增两个集合纳入同一持久事务和备份；不会把已有普通待办自动转换成每日模板。

跨月移动涉及多个 JSON，不能只靠各文件单独 rename 保证一致性。因此每次提交先原子写入并 fsync 完整恢复日志，再更新发生变化的文件，最后更新索引并移除日志。日志落盘后即是可恢复的提交；提交中读取方从日志取得完整快照。进程中断后，唯一写入服务在启动时重放日志。写入发生异常后拒绝后续提交，直到重启恢复，避免覆盖尚未恢复的事务。

目录不存在的月份文件会按需创建；索引引用的已有文件缺失或损坏时会拒绝启动，不将错误当成空日历。请通过 QQ/MCP/API 修改数据，**不要在服务运行期间直接编辑 JSON**。人工恢复前停止 DSH 并备份整个数据目录，按同一快照恢复索引、calendar 目录、daily-tasks、habits、history 和 state；不要只恢复其中一个文件。

## 同步范围

按服务器配置时区计算 **上个月、本月、下个月**，起点包含、终点不包含。例如 2026 年 10 月范围是北京时间 9 月 1 日 00:00 至 12 月 1 日 00:00。iCloud REPORT 请求携带对应的 UTC `time-range`；普通日程按与窗口相交判断，跨月持续的日程也可被读取。

- 月份滚动后，过去数据仍留在原 JSON，云端旧日程也保留；退出范围不会触发删除。
- 新建的窗口外未来日程先在本地归档，进入窗口后才上传，工具返回 `sync.state=archived`。
- 已同步事项从窗口内改到窗口外时，允许一次必要的读取或条件写入确认这次改期，然后停止跟踪。这可避免旧时间留在另一端，或把改期误判为删除。
- 日程在窗口报告中消失，需单独 GET 确认；只有连续两轮缺失且确认为 404 才导入删除。云端改到窗口外则归档，不删除。
- 习惯规则及其当次提醒始终留在本地，不创建或更新云端投影；每日必做的模板本身也不上传，生成的普通待办遵循相同三个月范围。升级后只清理窗口内本插件管理且未被人工修改的旧习惯投影，使用 ETag 条件删除；有改动则保留冲突，窗口外归档继续保留。
- 持久化重试移出窗口后暂停，不丢弃记录；`deferredPending` 与当前窗口的 `pending` 分开计数。

这个范围限制的是 iCloud 同步。QQ 可查询/编辑本地归档事项，已有提醒逻辑与共享记忆不因归档自动关闭。旧 Mac 配套程序是可选旧后端，不使用新的 iCloud 范围协议；启用直连后应继续保持它退出。

## 两个规则文件

`daily-tasks.json` 为 `{ "schemaVersion": 1, "items": { "模板ID": { ... } } }`。每个模板的可编辑字段为 `title`、`notes`、`defaultStartTime`、`defaultDurationMinutes`、`timeZone`、`enabled`；开始时间和持续时间必须显式提供。每天模板时区 08:00 后，在持久事务中检查当天是否已生成，再创建普通待办。模板与当地日期构成生成身份，重启和重复调度不会覆盖已生成、修改或删除的实例；停机不会批量补历史日期。

`habits.json` 为 `{ "schemaVersion": 1, "items": { "习惯ID": { ... } }, "occurrences": { ... } }`。规则保留内部 `kind=habit` 的现有执行模型，并提供默认墙钟时间 `defaultTime`。新建规则默认每日运行；新 API 的可编辑字段为 `title`、`notes`、`defaultTime`、`timeZone`、`enabled`。催促正文仍放在 `history.json`，与普通待办共同进入 Agent 记忆。任何回复只确认当次 occurrence，明确完成也只完成当次，不移动规则的默认时间。


## 独立余额状态

开启余额监测后，`balance.json` 使用独立 schemaVersion 1，保存账户绑定摘要、最近成功查询的余额、查询和重试时间、错误、已确认的余额不足证据，以及待发送通知和冷却记录。它不保存 API key；凭据仍由 DSH 解析。金额按币种保留十进制字符串，查询失败不清空成功缓存，也不写入一个虚构的 0。

余额文件由监测器串行更新并原子替换，权限为 600；它独立于月度日历事务和 `backup/` 中的日历分文件快照，不进入 iCloud 同步、每日模板、习惯或 Agent 的日历历史。备份整个数据目录会包含此文件；只恢复日历快照不会同时恢复余额告警状态。

查询状态与通知状态分别保存。通知发送前先记录在途状态；重启发现发送结果不确定时保留冷却，不立即重复发送。发送失败按独立退避重试；切换查询账户会丢弃旧账户缓存与待发通知，不把旧余额归到新账户。文件损坏或写盘失败时拒绝静默覆盖，排查前先备份原文件。配置和查询入口见 [余额功能](BALANCE.md)。
