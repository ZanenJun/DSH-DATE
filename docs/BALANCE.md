# DeepSeek API 余额查询与提醒

余额功能直接读取 DeepSeek API 账户余额，用固定 QQ 消息通知管理员，不调用模型生成正文。它与日历同步、每日待办、习惯及 30 秒催促各自运行；不会创建日历事项或把余额状态写入聊天记忆。

这里显示的是该 API 账户的总可用余额、赠金和充值余额，不是本插件单独消耗的费用。其他程序使用同一账户产生的费用也会反映在余额中。

## 开启

在日历插件配置文件中加入以下配置，重启 DSH 后生效。默认关闭；无需另外填写 API key。

```json
{
  "balance": {
    "enabled": true,
    "intervalMs": 3600000,
    "activeIntervalMs": 600000,
    "cooldownMs": 86400000,
    "timeoutMs": 10000,
    "thresholds": {
      "CNY": { "low": "5.00", "critical": "1.00" }
    }
  }
}
```

省略 `balance.providerId` 时跟随 DSH 默认模型的 provider；也可以填 DSH 中现有的 provider ID 固定查询目标。凭据通过 DSH 的凭据服务或其配置的环境变量引用解析，不从 QQ 获取，不写入日历配置或 `balance.json`。

当前适配只接受模型 provider 使用的这些官方地址：`https://api.deepseek.com`、`https://api.deepseek.com/v1`、`https://api.deepseek.com/anthropic`，均可带结尾斜杠。余额请求固定发送到 `https://api.deepseek.com/user/balance`。第三方中转、代理地址、自定义认证头覆盖或不能可靠解析的凭据不作为可查询目标，也不会把 API key 发送到它们的余额接口。

更换默认 provider、账号或凭据后，旧账户缓存与待发送通知不会沿用为新账户余额。若指定了 `providerId`，其他 provider 的调用和报错不会计入该账户。

## QQ 直接查询所需的桥接适配

在插件项目目录执行：

```bash
node bin/qq-balance-setup.js /absolute/path/to/qq-bridge
```

安装器只识别已支持的桥接消息入口，备份完整原文件、保留其他本地修改并原子写入；重复运行不会重复插入，未知版本会停止修改。完成后重启 qq-bridge。桥接源码更新后可以重新运行检查。

这一步是 QQ 绕过 Agent 查询余额的必要集成；仅安装日历插件不会改变桥接的消息入口。支持两种模式：

- `chat`，配置 `agentPreset: "calendar-assistant"`。
- `closed-agent`，选择 `closedAgentPreset: "calendar-assistant"`。

DSH 和 qq-bridge 必须使用相同的 `DSH_HOME`，或者在两者的服务环境中设置同一个 `DSH_CALENDAR_CONFIG`。只在安装命令所在终端设置环境变量，不会改变已经运行的服务。桥接按该配置取得回环地址和 `dataDir/access-token`，并核对管理员、机器人 QQ 身份。

管理员在私聊中发送纯文字 `查余额`、`查询余额` 或 `/balance`，桥接直接调用本地余额接口并回复结果。消息不进入 Agent，不触发语音转写；模型余额耗尽时也能处理，但 DSH 中的日历服务和 QQ 连接仍需运行。语音、带引用或其他媒体的消息，以及“请帮我查余额”等非精确指令继续走原对话流程。

手动查询新发起的查询不会为本次发现的低余额档位另发自动通知。若合并到了正在运行的自动查询，或已有 402 紧急告警，这些通知仍独立处理，可能与查询回复同时到达。作为管理员的普通来信，“查余额”仍会被日历消息 hook 记录，并暂停已经发出的待办/习惯催促。

## 查询时机与通知时机

| 触发 | 行为 |
| --- | --- |
| 插件启动 | 开启监测后请求一次余额 |
| 后台定时 | 默认每 1 小时检查；查询失败会退避重试 |
| 正在使用模型 | 对应账户的实际模型回合结束后，距最近成功查询达到 10 分钟才刷新 |
| 余额不足错误 | 对应 provider 返回结构化 402 时，记录不足并独立发送固定提示；首次不足请求刷新，重复 402 按活跃间隔和失败退避节流 |
| QQ / CLI 手动查询 | 立即请求刷新；同时到来的查询合并执行 |

活跃检查使用 DSH 模型请求/回合 hook，并关联请求实际使用的 provider 与账户绑定。它不按消息正文猜测错误，也不把其他模型或已经切换的旧账户的迟到 402 算到当前账户。余额查询不挂在每 20 秒日历同步或每 30 秒催促上。

默认按 CNY 可用余额分档：大于 5 元为正常，1 元以上且不超过 5 元为偏低，不超过 1 元为严重偏低。接口显示账户额度不可用，或对应模型返回 402 时，记录为余额不足。

自动通知在进入更严重档位时发送；余额持续偏低时，重复通知默认至少间隔 24 小时。恢复后会重新判断并发送恢复提示。QQ 发送失败和余额查询失败分别记录；发送失败会退避重试，不能把“查到余额”当成“已经通知用户”。不会按待办的 30 秒间隔反复催充值。

金额始终按币种处理，保留十进制字符串，不进行汇率换算。USD 默认没有金额阈值；需要时在 `thresholds` 中同时保留 CNY 并添加例如 `"USD": { "low": "2.00", "critical": "0.50" }`。这两个美元数值只是独立阈值示例，与人民币阈值不存在换算关系。`low` 必须大于 `critical`，两者均为正数字符串。未配置某币种的阈值时，仍展示该币种余额并处理明确的余额不可用证据。

## 查看状态与故障

以下命令使用与插件相同的配置位置，需在日历服务运行时执行：

```bash
node bin/calendar.js balance-status
node bin/calendar.js balance-refresh
```

`balance-status` 只读取状态和上次成功结果；`balance-refresh` 请求实际查询。可使用 `--config /absolute/path/config.json` 指定配置文件。返回内容包括面向用户的 `text`、成功查询时间、余额档位、查询错误以及通知状态。

DeepSeek 查询失败时保留上次成功余额，回复明确标记为缓存并显示查询时间，不能将缓存称为当前余额，也不会把失败替换成 0。没有缓存时说明暂不可查询。若本地日历服务都无法连接，桥接直接发送固定失败提示，不再让 Agent 重复回答。收到过 402 后，也不会仅凭一份未变化的旧余额声称已经恢复。

配置和缓存说明见 [存储布局](STORAGE.md)，本地 HTTP 接口见 [协议](PROTOCOL.md)。本功能必须在 DSH 插件环境中取得 provider 和凭据；单独启动数据服务不会自动获得 DSH 的模型账户。
